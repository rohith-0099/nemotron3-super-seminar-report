\chapter{Background}
\label{ch:background}

This chapter introduces the three building blocks of \NS: the Transformer and
its KV cache, state-space models, and Mixture-of-Experts layers.

\section{The Transformer and the KV Cache}

For $n$ tokens stacked as $X \in \mathbb{R}^{n \times d}$, self-attention
forms $Q = XW_Q$, $K = XW_K$, $V = XW_V$ and computes~\cite{vaswani2017attention}
\begin{equation}
  \operatorname{Attention}(Q,K,V) =
  \operatorname{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V .
  \label{eq:attention}
\end{equation}
The matrix $QK^{\top}$ has one entry for every pair of tokens, so any token can
retrieve information from any other in one step, but time and memory grow as
$O(n^2)$ (Figure~\ref{fig:complexity}).

\begin{figure}[!htbp]
  \centering
  \input{figures/tikz/complexity}
  \caption[Quadratic cost of self-attention versus linear cost of Mamba]{Relative
  per-layer cost of self-attention, $O(n^2)$, and of a Mamba layer, $O(n)$
  (drawn by the author).}
  \label{fig:complexity}
\end{figure}

Text is generated one token at a time, and each new token must attend to all
earlier ones. Recomputing their keys and values at every step would be
wasteful, so they are stored in a \emph{KV cache}, which grows by one entry per
layer for every token. The cache removes redundant computation but introduces
two costs that grow with the context (Figure~\ref{fig:kvcache}):
\begin{itemize}
  \item \textbf{Memory.} The cache holds one entry per past token per
        attention layer, so it grows linearly and without bound.
  \item \textbf{Time per token.} Every new token must read the whole cache, so
        generating a token gets slower as the context grows, and generating a
        whole sequence costs time quadratic in its length.
\end{itemize}
More cache means fewer requests fit on a GPU and each runs more slowly. GQA
reduces the size of each entry but not the way the cache scales, so for very
long-context tasks a pure Transformer remains expensive.

  \centering

  \caption[KV cache growth versus a constant-size SSM state]{An attention layer
  appends one key--value entry per token, whereas a Mamba layer overwrites a

  \label{fig:kvcache}
\end{figure}

\section{State-Space Models}

A state-space model maps an input $x(t)$ to an output $y(t)$ through a hidden
state $h(t)$, with $h'(t) = A\,h(t) + B\,x(t)$ and $y(t) = C^{\top} h(t)$.
Discretising with step size $\Delta$ gives the recurrence~\cite{gu2021s4,gu2023mamba}
\begin{equation}
  h_t = \bar{A}\,h_{t-1} + \bar{B}\,x_t, \qquad y_t = C^{\top} h_t ,
  \label{eq:ssm-disc}
\end{equation}
with $\bar{A} = \exp(\Delta A)$. The model reads one token at a time and keeps
a small ``note'', the state $h_t$, which has the same size whether the text is
one thousand or one million tokens long (Figure~\ref{fig:ssm}). Processing $n$
tokens costs $O(n)$, and each generated token costs the same regardless of
context length.

\end{figure}

\subsection{Mamba}

In S4 the matrices are fixed, so every token is written into the state in the
same way. Mamba~\cite{gu2023mamba} makes them depend on the input,
$h_t = \bar{A}(x_t)\,h_{t-1} + \bar{B}(x_t)\,x_t$, so the model can
\emph{select} what to remember: unimportant tokens leave the state almost
unchanged, important ones overwrite it. The Mamba block wraps this selective
SSM with a projection, a short convolution and a gate
(Figure~\ref{fig:mamba-block}).

  \label{fig:mamba-block}
\end{figure}

\subsection{Mamba-2 and State Space Duality}
\label{sec:mamba2}

Unrolling the recurrence shows that the whole layer is one matrix product
$y = Mx$ with $M_{ji} = C_j^{\top} A_j \cdots A_{i+1} B_i$ for $j \ge i$.
Dao and Gu~\cite{dao2024mamba2} show that a restricted masked attention
produces the same family of matrices (\emph{state space duality}). Mamba-2 uses
both views: during training the sequence is split into chunks computed with
fast matrix multiplications, and states are passed between chunks with the
recurrence, making it 2--8$\times$ faster than Mamba; during generation it
keeps a constant-size state. Its block is also simplified for parallelism
(Figure~\ref{fig:mamba2-block}).

\begin{figure}[!htbp]
  \centering
  \includegraphics[width=0.62\linewidth]{mamba2-fig06-block.pdf}
  \caption[The Mamba-2 block]{The Mamba-2 block produces the SSM parameters in
  parallel at the start of the block. \source{Dao and Gu
  (2024)~\cite{dao2024mamba2}, Fig.~6}}
  \label{fig:mamba2-block}
\end{figure}

Because everything about the past must fit into a fixed-size state, an SSM is
weak at exact recall, such as copying a phone number from a long list, where
attention excels~\cite{waleffe2024empirical}. Table~\ref{tab:attn-vs-ssm}
summarises the contrast that motivates hybrid models.

\section{Mixture-of-Experts}

An MoE layer~\cite{shazeer2017moe} replaces the single feed-forward network
with $N$ smaller \emph{experts} and a \emph{router}. For each token $x$ only
the $k$ highest-scoring experts run:
\begin{equation}
  y = \sum_{i \,\in\, \operatorname{TopK}(g(x),\,k)} g_i(x)\, E_i(x).
  \label{eq:moe}
\end{equation}
Here $g(x)$ is the vector of router scores and each expert $E_i$ is a small
two-layer network. The total parameter count grows with $N$, while the compute
per token grows only with $k$ (Figure~\ref{fig:moe}), so a model can be very
large and still cheap to run. Sparse routing brings its own problems:
\begin{itemize}
  \item \textbf{Load balancing.} If the router favours a few experts, the rest
        are wasted. GShard~\cite{lepikhin2020gshard} adds an auxiliary loss
        for even usage; DeepSeek-V3~\cite{deepseek2024v3} adjusts a per-expert
        bias instead.
  \item \textbf{Memory.} All $N$ experts must be loaded even though only $k$
        run for a given token.
  \item \textbf{Bandwidth and communication.} Each token may use different
        experts, so the weights to be read change from token to token, and in
        multi-GPU serving tokens must be sent to the device holding their
        experts.
\end{itemize}
These hardware costs are the starting point for LatentMoE
(Chapter~\ref{ch:arch}).

\section{Summary}

Attention gives exact access to every past token at a cost that grows
quadratically with the context, while a state-space layer such as Mamba-2
processes the sequence in linear time with a fixed-size but lossy state.
Mixture-of-Experts layers add capacity without adding computation per token,
at the price of memory and communication overheads. \NS\ combines all three:
Mamba-2 for efficient sequence processing, a few attention layers for exact
recall, and a hardware-aware MoE for capacity. The next chapter describes how
these pieces are arranged.
